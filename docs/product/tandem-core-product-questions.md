# Tandem 核心产品决策

## 产品定义

Tandem 是面向 AI 项目创造者的本地优先个人 AI 驾驶舱。用户只需说明要完成的事；Tandem 负责准备安全的工作现场、推荐并启动合适的 AI 工具、维持跨工具任务连续性，并把用户确认过的有效工作方式沉淀为可复用的个人搭子。

Tandem 不提供新的聊天窗口、编辑器或云端开发环境。原生工具继续负责执行，CC Switch 继续负责原生配置能力，Tandem 负责任务、工作现场、接力和个人工作方式。

核心循环：

> 导入现有工具与工作方式 → 说出要完成的事 → 推荐并安全启动 → 随时回到现场 → 必要时跨工具接力 → 用户确认后沉淀工作方式。

## 1. 首批用户

**决策：聚焦 AI 项目创造者，不以 Git 熟练度作为使用门槛。**

第一阶段用户同时具备以下特征：

- 正在用 AI 创建软件、自动化或数字产品，而不只是聊天问答。
- 每周使用两个及以上 AI 工具，已经感受到配置、任务和上下文割裂。
- 能描述目标和判断结果，但不愿管理 Git、worktree、终端配置、模型协议和配置文件。

候选工具包括 Claude Code、ChatGPT、Cursor、Antigravity、OpenCode、Helm、OpenClaw 等。产品 catalog 必须区分具体入口和真实能力，例如 Claude Code 与 Claude 网页不能视为同一种接入。

第一阶段不覆盖纯办公聊天、团队管理后台、移动端独立执行，以及没有本机项目的通用问答。

## 2. 每日入口

**决策：新任务优先，任务连续性常驻。**

- 首屏最大主动作是“开始一件事”。
- 当前进行中的任务紧邻主动作，提供一次点击“回到现场”。
- 任务全局是一级入口，按进行中、等待用户和已完成组织，而不是按工具分组。
- 任务启动后，Tandem 只显示可验证状态，并提供返回原生工具的最短路径。
- Provider、TokenKey 和工具配置保留完整能力，但不占用首页主叙事。

## 3. 首次价值

**决策：第一次惊喜是 10 秒内启动真实任务，不是“配置导入完成”。**

首次使用时，Tandem 先只读扫描已安装工具、现有 Provider、Skills、Rules 和可恢复会话索引。扫描阶段不改写 live 配置。

用户选择项目、输入目标并确认后，在正常就绪的本机环境中，Tandem 应在 10 秒内完成工具推荐、建立独立工作现场并启动目标工具进程。任务随即进入任务全局，用户可以在 Tandem 和原生工具之间往返。

10 秒指标从用户确认开始，到目标工具进程启动为止，不包含首次安装、缺失依赖修复、异常网络下载或 Agent 完成任务的时间。这些情况必须显示具体步骤和可恢复状态，不能伪装成静默等待。

现有官方登录可用时优先复用。TokenKey 是降低多工具配置成本的加速器，不是首次价值前的注册墙。配置、Rules、Skills 和会话索引可以导入；推断出的习惯只能成为待确认提案。

## 4. Git 与工作现场

**决策：用户使用“版本保护”和“独立工作现场”，无需主动理解 Git 或 worktree。**

- 日常界面只使用“项目”“独立工作现场”“版本保护”和“可恢复”。
- `origin/main`、SHA、分支和 worktree 路径仅在技术详情、故障恢复和专家模式中展示。
- 默认确认页只说明从哪个项目版本开始、是否影响原项目，以及失败后能否恢复。
- 第一阶段以 Git 项目作为可靠执行边界，但不要求用户会 Git。

非 Git 项目可以导入和扫描，但首次任务前必须进入独立的“开启本地版本保护”流程。该流程先检查敏感文件和忽略规则，展示计划并获得确认；`start_task` 不得静默执行 `git init` 或提交全部文件。

## 5. 工具与模型推荐

**决策：Tandem 推荐，用户决定。**

第一阶段提供三个推荐策略，与商业付费套餐分离：

- **最佳效果**：优先成功率和复杂任务能力。
- **均衡完成**：综合能力、速度和预计成本，作为默认策略。
- **节省成本**：满足任务门槛后优先低成本工具与模型。

每次只展示一个首选、一个备选和一句主要理由。能力、成本、速度、当前可用性、项目历史效果和已确认偏好参与排序，但不形成首页仪表盘。

用户可以在启动前一键覆盖。单次覆盖只影响当前任务；重复出现后形成待确认的路由偏好，确认后才进入长期搭子。

## 6. 跨工具接力

**决策：Tandem 保证任务连续性协议，不承诺转换工具的私有会话历史。**

标准接力包包含：

- 任务目标与完成标准。
- 已完成、待完成和当前阻塞。
- 用户确认过的决策与约束。
- 相关文件、改动摘要和工作现场状态。
- 已执行的验证、结果与失败信息。
- 推荐的下一步。
- 当前任务可用的项目规则、个人规则和 Skills 引用。
- 明确排除的凭据、私有会话正文和敏感数据。

接力包使用一份工具无关的结构化 SSOT，再由 ToolAdapter 生成目标工具所需的提示或本地文件。用户只需在产生副作用前确认摘要和敏感内容边界。

接力状态分为：

- **已打开**：目标工具打开同一工作现场。
- **上下文已送达**：目标工具收到标准接力包。
- **已接手**：目标工具确认目标，并开始或完成一个可验证的下一步。

只有能达到“上下文已送达”的适配器才标记为“可接力”；只能启动的工具显示“只能打开”。

## 7. 封闭工具能力

**决策：不做统一承诺，按版本和操作系统实测后分级。**

Tool Capability Matrix 记录：

- 安装检测和启动。
- 指定项目或工作现场打开。
- 初始任务或接力包注入。
- Provider、模型和环境变量控制。
- 原生会话发现、恢复和关联。
- “上下文已收到”或任务结果信号。
- 已知限制、失败表现和最后验证时间。

适配器分为：

- `Native`：完整启动、上下文注入和会话恢复，展示“完整接力”。
- `Handoff`：同一工作现场加标准接力包，展示“文件接力”。
- `Launcher`：只负责打开，展示“只能打开”。

矩阵必须由真实 UI e2e 验证，并与适配器 manifest 一起版本化。工具升级后，旧结论自动变为“待验证”。完成首轮工具实测后，本项才能从“待实测”转为最终决策。

## 8. 个人工作方式

**决策：一个工具无关的个人工作方式 SSOT，按需编译为各工具载体。**

每条知识包含内容、类型、作用域、来源证据、确认状态、有效期和敏感级别。只沉淀五类内容：

- **偏好**：表达、交互和结果呈现方式。
- **规则**：必须遵守或禁止的决策边界。
- **流程**：可重复执行的工作步骤，成熟后可提升为 Skill。
- **验证方法**：测试、检查清单和 harness。
- **路由经验**：什么任务在什么工具和模型上表现更好。

Companion Compiler 从 SSOT 生成 Skill、Rule、Memory、Harness 或 Prompt。派生文件不是新的事实来源。

系统可以自动发现候选，但只有用户确认后才能进入长期 SSOT。项目事实和临时任务状态不得混入长期记忆。删除 SSOT 条目后，所有派生文件必须同步撤销。

## 9. CC Switch 上游继承

**决策：第一阶段采用同仓、双 remote、merge-friendly fork，暂不插件化。**

- Tandem 仓库拥有自己的 `origin`，CC Switch 保持为 `upstream`。
- 原生组件和服务默认保持编译、可访问和上游所有权，禁止为了简化体验直接删除。
- Tandem 领域代码进入独立目录和伴生模块；上游文件只保留 route 注册、import 和调用等薄注入点。
- Tandem 功能 PR 可以 squash；上游同步使用保留祖先关系的 merge commit。
- CI 检查上游漂移、冲突面、原生能力契约、上游文件删除和注入侵入度。
- 固定节奏同步上游；新增能力默认进入原生配置面，删除或替换必须有产品审批。

ToolAdapter 和 Companion Compiler 边界稳定后再开放插件 API。第一阶段不冻结尚未验证的扩展契约。

## 10. 本机信任

**决策：采用策略、执行、审计、恢复闭环；借鉴 CubeOS 思想，使用现代桌面安全原语实现。**

1. **策略层**：启动前生成可读计划，包括授权项目根、目标工具、允许注入的环境变量、预计文件与 Git 副作用、网络需求和风险等级。
2. **执行层**：只接受结构化参数和短期 capability grant。UI 不拼接任意 shell，ToolAdapter 不能获得当前任务之外的权限。
3. **审计层**：独立记录脱敏事件、结果和恢复凭证，不记录完整项目内容、提示词、私有会话正文或 secret。
4. **恢复层**：为配置写入、工作现场创建和规则生成保留备份或撤销动作。

数据边界：

- 凭据只进入系统 Keychain 或工具安全存储，UI、交接包、日志和云端都不可见明文。
- 项目内容和原生会话正文默认只在本机，只对已授权项目和工具开放。
- 个人工作方式默认本机保存；同步必须逐类开启、端到端加密，密钥留在用户设备。
- 工具安装、模型能力等低敏元数据可以用于推荐，上传前仍需最小化和脱敏。

权限采用渐进授权：首次扫描只读；选择项目时授予项目根；配置改写、工作现场创建、接力、清理和远程控制按风险展示计划。远程控制必须通过设备密钥配对、短期范围令牌和本机可见的撤销入口，浏览器不能直接获得文件系统或任意命令能力。

## 第一阶段完成标准

- 用户无需理解 Git，即可安全开始和恢复真实任务。
- 正常就绪环境下，从确认到目标工具进程启动不超过 10 秒。
- 当前任务可一次点击回到原生工具现场。
- 每个展示为“可接力”的工具均有版本化的真实 UI 验证证据。
- 跨工具接力能可靠送达标准接力包，并显示真实接力状态。
- 学习候选经用户确认后进入个人工作方式 SSOT，并能同步生成或撤销工具载体。
- CC Switch 原生能力不因 Tandem 的信息架构调整而丢失。
- 明文凭据、完整项目内容和私有会话正文不进入云端、日志或接力包。

当前唯一未完成的产品判断是第 7 项 Tool Capability Matrix；它需要逐工具实测，而不是继续讨论。
